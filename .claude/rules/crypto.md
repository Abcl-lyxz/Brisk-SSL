# Crypto rules (Brisk-SSL)

- Constant time on secrets: no secret-dependent branch, index, loop bound, `/` or `%`; no
  T-table AES (bitsliced `aes_ct`/`aes_ct64` style). Compare MACs/tags with `brisk__ct_memeq`.
- Wipe every key, secret, scratch buffer and stack copy of a context with `brisk__secure_zero`;
  AEAD open wipes the output on authentication failure.
- Validate untrusted inputs before use (field elements < p, points on curve, all-zero X25519
  output rejected) and fail closed.
- Every primitive ships with official KATs + Wycheproof (valid **and** invalid) + a seeded
  differential set, generated by `tools/kat.py` (`/kat`). Get a `crypto-reviewer` pass before commit.
- Cite the spec in comments: FIPS 180-4, RFC 8439, RFC 7748, SP 800-38D, RFC 6979, RFC 8017...;
  TLS 1.3 = RFC 9846 (not 8446).
- Suite order: ChaCha20-Poly1305 first on CPUs without AES instructions; AES-128-GCM always
  compiled (TLS 1.3 mandatory suite, QUIC Initial packets).
- Third-party code: fiat-crypto files live untouched in `vendor/fiat/` (edits are blocked by a
  hook) with the upstream commit in `vendor/VENDORED.md`. Code adapted from BearSSL (MIT) or
  anything else keeps its copyright notice in the file header **and** in `NOTICE`.
- RNG: `getrandom()` then `/dev/urandom` fallback, fail closed, never seed from time/PID; no
  userspace DRBG (fork safety). ECDSA signing uses hedged RFC 6979 nonces.
